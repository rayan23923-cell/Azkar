## What was implemented

- **`Packages/IslamicCore`**: a Swift package (tools 5.9, iOS 17 / macOS 14) that uses only Swift and Foundation. It imports no UIKit, SwiftUI, AVKit or AVFoundation.
- **Quran domain**: `QuranSurah` (id, Arabic name, transliteration, English name, ayah count, revelation type, revelation order, basmala), `QuranVerse` (surah id, ayah number, Arabic text) and `QuranReference` (a run of whole verses).
- **Adhkar domain**: `DhikrGroup` (morning, evening, afterPrayer, sleep, general) and `DhikrItem` (id, group, order, Arabic text, source, repeat count, Quran reference, review status).
- **Dua domain**: `DuaCategory` (quranic, prophetic) and `DuaItem` (id, category, order, Arabic text, source, Quran reference, review status).
- **`ContentReviewStatus`**: `QURAN_VERBATIM_TANZIL`, `CONTENT_REVIEW_REQUIRED` or `REVIEWED`.
- **`SessionCursor`**: the current item, `next`, `previous`, `jump` and bounds. `advance()` counts one repetition and moves on only after the current item's `repeatCount` is complete. `next`/`previous` are explicit navigation and reset the repetition count.
- **`QuranSession`, `DhikrSession`, `DuaSession`**: content and a cursor only. They have no audio or PiP.
- **State enums**: `SessionState`, `PlaybackState`, `PiPState` and `AudioState`, with exactly the cases in the spec and no behaviour.
- **Repository protocols**: `QuranRepository`, `DhikrRepository` and `DuaRepository`, all `async throws`. The bundled implementations are actors that read JSON resources lazily and cache them. `BundledContentSource.data(_:)` lets tests feed invalid content.
- **Offline content**: three JSON files under `Sources/IslamicCore/Resources/Content`, generated by `tools/content/build_content.py`.
- **CI**: a new `IslamicCore tests` job runs `build_content.py --check` and `swift test`. The existing app build job is unchanged and now also runs on `feature/**` branches.

## Content sources

| Content | Source | How it gets into the app |
|---|---|---|
| Quran text | Tanzil Quran Text (Uthmani, Version 1.1), downloaded on 2026-10-08 by a GitHub runner, because tanzil.net is blocked from the build container | The `text` of every `<aya>` in `quran-uthmani.xml` is copied character for character into `quran.json`. Nothing is normalized |
| Basmala | Tanzil `bismillah` attribute on verse 1 | Stored in `QuranSurah.bismillah`, separate from the verse text. It is nil for Al-Fatiha, where it is verse 1, and for At-Tawba |
| Surah metadata | Tanzil `quran-data.xml` | Names, transliteration, English name, type and revelation order |
| Quranic adhkar and duas | The same Tanzil text | Referenced by `quranRef` (whole verses only). The text is joined from Tanzil by the script, never typed by hand |
| Prophetic adhkar and duas | Transcribed by the project, with the hadith source given per item | Marked `CONTENT_REVIEW_REQUIRED` |

Upstream SHA-256 values are checked by a test:

| File | SHA-256 |
|---|---|
| `quran-uthmani.xml` | `c5052534d63d3856ce25413ff464d0b609f90169a202a1615aa8707efec81244` |
| `quran-uthmani.txt` | `7f30c647331a61100ebf24a80507dc0fcdd9f2df97f1312b5b2dfcb982a7f326` |

## Known issues

1. 40 transcribed adhkar and duas are `CONTENT_REVIEW_REQUIRED` and need a qualified reviewer.
2. Quranic adhkar (Al-Ikhlas, Al-Falaq, An-Nas, Ayat al-Kursi) are stored without a basmala prefix. Whether to show one before them is a UI decision.
3. Tanzil spells surah 14 as "ابراهيم" (no hamza). It is kept verbatim.
4. The test target imports CryptoKit, which is available on macOS and iOS. On Linux the SHA test is skipped.
5. `quran.json` is about 1.4 MB uncompressed in the app bundle. This is acceptable for V1.
6. No Quran font is bundled yet (planned for Phase 5 with the renderer work).
